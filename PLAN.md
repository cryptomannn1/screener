# Скринер: состояние и план действий

Дата: 12.11.2026.

Скринер для терминала Scope360: таблица бессрочных контрактов сразу по трём биржам, OKX, Binance и Bybit. Сервис собирает данные и отдаёт их по HTTP, интерфейс показан прототипом и перенесён в Vue-компонент. В терминале скринер будет отдельной страницей, а не виджетом рабочего стола.

## Что в репозитории

| Путь | Что это |
|---|---|
| `cmd/`, `internal/` | Сервис на Go: сборщики бирж, расчёт метрик, HTTP API, запись в ClickHouse |
| `api/screener.md` | Контракт API |
| `prototype/` | Прототип интерфейса одной страницей и его исходник |
| `widget/` | Vue-компонент скринера для страницы терминала. Папка названа по первому замыслу |
| `docker-compose.yml`, `deploy/` | ClickHouse для хранения |
| `README.md` | Устройство сервиса, циклы сбора, флаги запуска |

## Как запустить

Нужен Go 1.25 или новее. Docker нужен только для хранилища.

```bash
go run ./cmd/screener -static prototype
```

Открыть http://localhost:8090/ui/screener-v2.html. Первые 3–4 минуты сервис прогревается: дочитывает открытый интерес Binance и свечи активов, которых нет на OKX.

С хранилищем: `make ch-up`, затем та же команда с флагом `-clickhouse` (строка подключения в Makefile, цель `run-ch`). Порты 9000 и 8123 должны быть свободны.

Проверка кода: `make test`.

Страницу прототипа можно открыть и без сервиса, просто файлом: она покажет встроенный снимок данных.

## План

### Этап 1. Закрыть текущее

Объём малый, всё внутри этого проекта.

1. Добавить вкладки Funding и Levels, если они нужны.
2. Подтвердить допущения прототипа (список ниже, в разделе открытых решений).

### Этап 2. Страница скринера в терминале

Таблица перенесена в Vue, остались панель актива и встраивание.

1. Сделано: прототип таблицы перенесён в Vue-компонент. Он читает `/assets` и поток, сам складывает выбранные биржи, повторяет вкладки, фильтры-фразы, адаптивные ширины, разбивку по биржам и анимацию цены. Запуск песочницы: `make widget`, порт 5190.
2. Сделано со стороны компонента: всё состояние отдаётся наружу одним объектом настроек. В терминале его остаётся сохранять в `/settings` одним ключом страницы.
3. Панель актива, серверная часть: запрос с данными одного актива (описание, ссылки, предложение, FDV, максимум цены) и отдельный шаг, который пишет описание проекта простым языком по фактам источника и хранит готовый текст. Новые листинги описываются автоматически.
4. Панель актива в компоненте: перенос из прототипа. Клик по строке открывает панель, кнопка в ней ведёт на график.
5. Встроить страницу в терминал по процессу команды: маршрут, пункт навигации, замена локальных частей на компоненты терминала. Порядок описан в `widget/HANDOVER.md`.
6. Сопоставить актив и биржу с инструментом терминала, чтобы кнопка панели открывала рабочий стол с нужным графиком. `/assets` не отдаёт идентификатор инструмента биржи.

### Этап 3. Довести Binance и Bybit до уровня OKX

Объём большой, можно делать частями в этом порядке.

1. Писать их тикеры и свечи в ClickHouse. Сейчас они в памяти, поэтому после перезапуска нужен прогрев.
2. Сделки: поток покупок и продаж, дельта, скорость ленты для 403 активов, которых нет на OKX.
3. Стаканы: спред и глубина.
4. История открытого интереса: изменение OI за периоды. Заодно ускорить OI Binance, сейчас полный круг занимает около трёх минут.

### Этап 4. Выкладка для команды

1. Общий dev-хост: сервис и ClickHouse в docker compose, авторизация и ограничение частоты перед API, свой пароль ClickHouse вместо локального из compose.
2. Ключ CoinGecko с коммерческим планом. Публичный доступ разрешён только для некоммерческого использования.

### Этап 5. Дальше по продукту

- Ликвидации и соотношение лонгов и шортов как колонки.
- Периоды 5 и 15 минут.
- Свои вкладки пользователя: сохранить текущую таблицу как новую.
- Капитализация акций: нужен отдельный источник.
- Фундаментальные метрики протоколов: нужен платный источник с правом показа в продукте.

## Открытые решения

| Вопрос | Что сейчас |
|---|---|
| Модель строки при нескольких биржах | Объём и OI суммой, цена с самой объёмной биржи, фандинг к 8 часам по весу OI. Так же делают Coinalyze и CoinGlass |
| Класс по умолчанию | Crypto |
| Определение Strong и Weak | Опережает или отстаёт от BTC на 3–10% за сутки, объём от $10M |
| Вкладки Funding и Levels | Предложены, не сделаны |
| Состав панели актива | Прототип показан, состав и порядок блоков не утверждены |
| Язык описаний проектов | Английский, как весь интерфейс |

## Известные ограничения

- Открытый интерес Binance отстаёт на несколько минут: биржа отдаёт его по одному символу за запрос.
- Объём за 1 и 4 часа обновляется примерно раз в 2 минуты, вместе с минутными свечами. Изменение и объём за сутки считаются по часовым свечам, с оценкой внутри свечи.
- Поток сделок, стакан и изменение OI пустые для активов вне OKX.
- Данные Binance и Bybit живут в памяти сервиса.
- Вкладки Strong и Weak только описывают рынок. Бэктест на 183 днях показал, что сила против BTC не предсказывает движение.
- Taker buy и Delta за 24 часа появляются после суток работы потока сделок. Без хранилища перезапуск обнуляет счёт, с ClickHouse сделки OKX дочитываются при старте.
- Контракты с одним тикером, но ценой дальше 15% друг от друга, идут разными строками: это другая бумага или другой масштаб цены (ANTHROPIC и OPENAI на OKX и Binance).
- Сервис не закрыт авторизацией: годится для локальной работы, не для открытого хоста.
